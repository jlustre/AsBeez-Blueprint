# Introduction

The Membership Engine exposes business capabilities through secure, versioned, and standardized APIs.

These APIs allow applications, mobile clients, AI Agents, partner systems, and other Platform Engines to interact with Membership data without exposing internal implementation details.

The APIs focus on business operations rather than database operations.

---

# Purpose

The Membership APIs exist to:

- Manage Customers
- Manage Memberships
- Manage Qualifications
- Manage Sponsors
- Manage Referrals
- Manage Country Residency
- Manage Membership Policies
- Publish Membership Events

---

# API Principles

The Membership Engine follows the AsBeez Platform API standards.

- API-First
- RESTful
- Stateless
- Secure by Default
- Versioned
- Resource-Oriented
- Event-Driven
- Backward Compatible

The Membership Engine follows the platform-wide API conventions defined in the Platform API Standard.

---

# Base URL

```text
/api/v1/membership
```

Future breaking changes require a new version.

Example:

```text
/api/v2/membership
```

---

# Authentication

Every protected endpoint requires authentication through the Identity Engine.

Supported authentication methods include:

- Bearer Token
- OAuth 2.0
- OpenID Connect
- Service Accounts
- Internal Platform Authentication

Authentication is delegated to the Identity Engine.

---

# Authorization

Authorization is enforced by the Identity Engine.

Membership APIs require appropriate:

- Roles
- Permissions
- Policies
- Country restrictions
- Organization restrictions

# Business Operations

The Membership Engine exposes business capabilities rather than CRUD operations.

Examples include:

- Qualify Member
- Activate Membership
- Reactivate Membership
- Transfer Residency
- Assign Sponsor
- Record Referral
- Activate Pending Referrals
- Evaluate Qualification
- Determine Membership Status

---

# Standard Request Format

Requests use JSON.

Example:

```json
{
    "country": "US",
    "sponsorId": "MEM-100245"
}
```

---

# Standard Response Format

Successful responses follow the platform standard.

```json
{
    "success": true,
    "data": {},
    "meta": {},
    "links": {}
}
```

---

# Error Responses

Errors follow the platform standard.

```json
{
    "success": false,
    "error": {
        "code": "MEMBERSHIP_NOT_QUALIFIED",
        "message": "Customer has not yet qualified for Membership."
    }
}
```

Implementation details should never be exposed.

---

# Business Events

Successful API operations publish Membership events.

Examples:

```text
Customer Registered

↓

CustomerCreated
```

```text
Qualification Achieved

↓

MembershipQualified
```

```text
Membership Activated

↓

MemberActivated
```

The API performs business operations.

The Event Bus informs the remainder of the platform.

# Idempotency

The following operations should support idempotency.

- Qualification
- Membership Activation
- Residency Transfer
- Sponsor Assignment
- Referral Recording

Clients should provide an `Idempotency-Key` header where appropriate.

# Closing Statement

The Membership APIs provide a stable, secure, and business-oriented interface for interacting with Membership capabilities across the AsBeez ecosystem.

They expose business operations rather than internal implementation details, allowing every application and Platform Engine to interact consistently while preserving the integrity of the Membership domain.

---

# Guiding Principle

> **Expose Membership capabilities through secure, versioned, and business-focused APIs that provide a stable contract between the Membership Engine and every authorized participant, application, service, and Platform Engine.**
