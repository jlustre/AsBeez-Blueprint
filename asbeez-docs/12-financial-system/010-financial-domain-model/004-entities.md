# Entities

## Purpose

An entity has a stable identity and a lifecycle. Its attributes may change, but its identity and audit history must remain traceable.

## Entity Catalog

| Entity | Identity | Lifecycle concern |
| --- | --- | --- |
| Financial Account | account ID | open, restricted, closed |
| Payment | payment ID | initiated through refunded or disputed |
| Invoice | invoice ID | draft through settled, void, or uncollectible |
| Journal Entry | entry ID | prepared, approved, posted, reversed |
| Wallet | wallet ID | pending, active, frozen, closed |
| Wallet Hold | hold ID | placed, partially released, released, expired |
| Settlement | settlement ID | calculated, approved, processing, settled, failed |
| Payout | payout ID | requested, approved, submitted, paid, failed, cancelled |
| Tax Assessment | assessment ID | calculated, accepted, adjusted, remitted |
| Reconciliation Session | session ID | open, matching, reviewed, completed |
| Reward Liability | liability ID | pending, released, reversed, expired |

## Common Entity Attributes

Every financial entity includes an immutable identifier, owning context, status, version, created time, updated time, effective time, actor or system identity, jurisdiction, and audit correlation ID where applicable.

## Identity and Mutation

Identity is generated by the owning context and is never reused. Mutations occur through named commands, emit an event, and record the reason and actor. Sensitive values are minimized; payment credentials are represented by provider tokens or references, never raw card data.
