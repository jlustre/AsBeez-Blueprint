# Wireframe Assets

## Purpose

Wireframes describe early information architecture, navigation, layout, workflow, content hierarchy, and responsive behavior.

## Requirements

Record target role, task, device/viewport, state, requirements, assumptions, accessibility, privacy, owner, version, status, and linked product story/acceptance criteria.

## Controls

Wireframes are exploratory until approved. Financial actions must show authorization, confirmation, idempotency, pending/unknown/error states, source/freshness, and support/escalation paths.
