# Entity Relationship Model

## Purpose

The ERD describes relationships among platform identity, commerce, rewards, matrix, financial, event, configuration, and audit records while preserving bounded-context ownership.

## Conceptual Relationships

```text
Actor/Organization -> Membership/Role -> Orders/Products/Services
Order -> Payment/Invoice/Tax/Fee -> Settlement/Vendor/Partner Entitlement
Member -> Reward Activity -> RP/ABC/AHC -> Matrix Placement
Approved Financial Effect -> Subledger -> Journal -> Ledger Lines -> Reports/Reconciliation
Any Material Change -> Event/Outbox -> Projections/Audit/Integration
```

## Relationship Rules

Relationships use stable references and contract-owned identifiers. A foreign key or external reference does not grant another context permission to mutate the referenced record. Historical records retain original country/entity/currency/policy; current profile state must not rewrite historical facts.

## Financial Constraints

Journal-to-line is one-to-many; journal lines map to accounts/dimensions; subledgers reconcile to control accounts; payments/refunds/payouts/reserves/tax/FX link source and accounting references; projections point to source positions; audit references resource/version/action without replacing source data.
