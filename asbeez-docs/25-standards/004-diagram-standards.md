# Diagram Standards

## Purpose

Diagrams communicate architecture, context, workflows, state, data, sequence, ownership, and controls without becoming an unversioned source of contradictory truth.

## Required Metadata

Title, purpose, scope, owner, version/date, source documents, actors/contexts, assumptions, country/entity/currency/period where relevant, legend, status, and review date.

## Rules

Use approved notation, directional flow, clear boundaries, explicit authority, consistent names, accessible labels, and limited complexity. Mark commands, events, external evidence, projections, ledger authority, human approval, compensation, and failure/unknown paths distinctly.

## Maintenance

Review diagrams when architecture, schema, API/event contracts, policies, providers, workflows, or ADRs change. Test links/rendering and preserve historical versions where they explain past decisions.
