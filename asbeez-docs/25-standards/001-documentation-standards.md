# Documentation Standards

## Purpose

Documentation must be discoverable, accurate, versioned, navigable, accessible, and suitable for implementation, operations, audit, legal review, and decision-making.

## Required Structure

Use one H1 title, concise purpose, scope/authority where relevant, clear H2/H3 sections, definitions, rules/requirements, examples or acceptance evidence, related links, owner/status/version, and revision history for controlled artifacts. Use ASCII by default unless existing content requires another character set.

## Content Rules

State source of truth, assumptions, unresolved decisions, scope, country/entity/currency/period, policy/version, actor/owner, security/privacy classification, and effective date. Distinguish actuals, estimates, forecasts, provider evidence, projections, and authoritative ledger facts.

## Quality

Use workspace-relative links, verify targets, avoid stale filenames, preserve headings, check formatting, keep examples consistent with rules, and validate links/structure after edits. Record supersession rather than silently overwriting decisions.
